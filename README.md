# 家人安心记

给家属使用的本机健康记录、饮食问答和提醒工具，支持上传仪表读数或食物照片，并附带一个可选的普通微信群 Windows 桥接程序。真实微信接入还需要匹配的客户端、`wxautox4` 授权和测试群验证。本项目没有安装微信依赖、登录账号或发送真实群消息。

默认关闭云端模型、所有定时提醒和真实微信收发。它是家庭辅助工具，不是实时医疗监护；漏收消息、掉线和发送失败都可能发生。出现新发卒中表现、意识异常等急症时，直接联系急救和家属，不要等待机器人回复。机器人不调整药量，也不把一次读数判断成“安全”。

## 先在网页里试用

需要 Python 3.10 或更新版本。图片校验使用 Pillow，Windows 首次双击 `setup.cmd` 安装到项目专用环境，随后双击 `start.cmd`。微信桥接依赖单独安装。也可在自己的 Python 环境、本目录运行：

```powershell
python -m pip install -r requirements.txt
python server.py --host 127.0.0.1 --port 8765 --open
```

网页地址是 <http://127.0.0.1:8765>。保持终端运行；关闭终端即停止服务。仅监听本机，不需要开放端口，也不需要公网域名。

双击 `stop.cmd` 可以停止本机服务（后台启动时也适用）。已经运行时再次双击 `start.cmd` 会打开现有服务，不会重复启动。模型费用可在设置页打开“查看模型费用对比”，或查看 `static/prices.html`；价格核验于2026-10-25，微信群接入授权另计。

从旧版更新：先双击 `stop.cmd`，再双击 `start.cmd`。在“家庭设置 → 照片识别”勾选启用，模型保留 `deepseek-flash`；已配置 DeepSeek 文字密钥时可选择同源复用后保存。仅替换文件或刷新网页不会更新内存中的旧后端；图片上传页面会提示服务尚未更新。版本可从 `/api/health` 查看，新版为 `0.2.0`。

1. 在“对话试用”输入 `血压 135/82 mmHg` 或 `空腹血糖 7.1 mmol/L`。这些数字只是输入格式示例，**不是爸爸的目标值**。
2. 核对待确认内容，再回复界面返回的 `确认 编号`；未确认不进入健康记录。也可以回复 `取消 编号`。试用数据带有试用来源，不能当成爸爸实际测量。
3. 试问“糖尿病可以吃水果吗”。未接云端模型时使用有限的本地回答；遇到超出范围的问题会提示补充信息。
4. 在“设置”填写家人资料和实际药名，核对医生给定的测量安排、饮食要求及个人数值范围。新安装的年龄、脑梗病程和健康情况默认留空或未知；程序不会推断这些信息。已有本机档案会继续从未入库的 `data/` 目录读取。
5. 在“提醒计划”按医嘱设置时间并启用所需条目。不要为了打卡自行增加测量或改变用药。服务必须持续运行才能处理到期任务；停机期间的任务不补发。

网页提供已确认记录的 CSV 导出。测试记录与微信记录有来源标记；请检查来源后再交给医生。家属提醒是群内文字消息，“已发送”仅表示接入程序报告发送成功，不代表家属读到或接手，也不保证微信原生 @ 提醒。程序不会自动打电话或发送短信。

每日菜单需要先填写并核对一周菜单，再启用对应提醒。尚未确认药物、肾功能和营养需要前，程序不会自行生成个人治疗食谱或克数。

## 图片：仪表读数和食物

网页可上传照片；连接真实微信后，爸爸和指定家属也可直接在群里发送图片消息。支持常见 JPEG、PNG、WebP 静态图片，每张最多 8 MiB；识别引擎也接受微信下载得到的 BMP。GIF、HEIC、视频、作为文件发送的附件及引用消息中的图片不属于当前支持范围。识别需要在设置中独立配置并启用图片模型，默认填写 `deepseek-flash`；可在相同 API 基础地址下复用文字模型的密钥。文字模型选择保持独立，不会因为开启图片识别而改掉已选的模型；只有文本能力的模型不能看图。

拍血压计或血糖仪时，让整个显示屏清晰可见、数字方向摆正，保留单位，避免反光。通过首次校验的仪器读数还会进行一次独立识别；两次数字、单位或类别不一致时不生成草稿。同一模型可能两次犯相同错误，因此一致结果也只是待核对内容，必须确认数字、单位、测量时间和血糖餐次后才保存。家属发来的仪表照片还需要确认测量对象，不能默认记到爸爸名下。小数点、屏幕标志和仪表存储的旧读数都可能被识别错；照片不能用于自动诊断，也不会自动修改药物。

图片读数在群里确认时，补上实际时间与血糖餐次，例如 `确认 编号 刚测 空腹`，或者 `确认 编号 2026-10-25 08:00 空腹`。血糖餐次可写空腹、餐前、餐后2小时或随机；血压不需要血糖餐次。家属代发的图片还须明确是爸爸，例如 `确认 编号 爸爸 刚测 空腹`。编号使用机器人实际返回的编号；示例日期不是你的测量日期。网页则填写实际测量时间，核对后点击“确认是爸爸的读数并保存”。

食物照片可用于询问一般搭配、烹调和份量原则；单张照片不能可靠确定糖含量、配料、重量或是否适合爸爸。具体饮食限制仍以已核对的医嘱为准。

开启图片识别后，照片会经本机服务发送到你配置的模型服务商处理，请避免拍入无关人员、证件和私人信息。微信桥接每张图片只临时下载到独立目录，校验路径和大小后上传，完成或失败后清理该临时目录；不会把图片归档进健康记录。微信客户端自身的图片缓存不由本程序管理。图片下载失败、超过大小限制或路径异常时，会请求后端在群内提示重发，不自动反复下载；界面群身份异常则停止桥接。

## 接入其他模型

在“设置 → 饮食问答的回答方式”填写服务商的 API 基础地址、模型名称和 API 密钥，再启用。文字问答支持兼容 `POST /chat/completions`、返回 `choices[0].message.content` 的接口；图片识别须另外确认所配置模型支持图片输入。程序会在基础地址后添加 `/chat/completions`。如果服务商要求 `/v1`，基础地址应包含 `/v1`。

密钥只在本机设置页输入，不要发到聊天或微信群。程序不会替你购买模型额度。启用后，相关问题及必要的家属填写资料会发送到你指定的服务商；健康记录处理、确认流程和急症提示使用本地规则。模型回答会标注为未经医生审核的饮食参考；连接失败时退回本地提示。提示词不能保证模型回答正确，涉及具体药物或饮食限制仍需核对医嘱。

## 可选：普通微信群桥接

此部分使用 `wxautox4` 操作 Windows 微信桌面界面，不是腾讯官方机器人接口。它按作者公开接口编写，尚未在你的微信版本和账号上验证。微信更新、锁屏、窗口重建、断网、登录失效或账号限制可能导致失效。需要一台保持登录、桌面可操作的 Windows 电脑；首次先用专门的测试群验证，再考虑家庭群。

### 依赖和授权

根据作者安装文档，当前针对微信 4.1，具体补丁版本仍需对照其兼容列表。Plus 文档支持 Python 3.9–3.13；建议为桥接单独准备 Python 3.12 环境。主程序可以继续使用现有 Python，包括更高版本。

`wxautox4` 是作者的 Plus 包，需要自行核对、获取适用授权；本项目不包含授权、不自动购买、不代激活。依赖未锁定具体版本，因为没有已实测通过的依赖和微信组合。安装前请查看作者当时的兼容要求、用户协议和授权条款；测试成功后记录所用 Python、包和微信版本。

如果已装好 Python 3.12，并已核对作者条款，可自行执行：

```powershell
py -3.12 -m venv .venv-wechat
.\.venv-wechat\Scripts\python.exe -m pip install -r requirements-wechat.txt
```

作者要求的授权步骤应按其文档完成。不要将微信密码、登录二维码、API 密钥或授权凭证发给不可信第三方。

### 连接顺序

1. 启动网页服务。在“微信连接”填写**唯一且完全一致**的群名、爸爸的群内显示名、接手家属的群内显示名，先保持真实收发关闭。
2. 电脑微信登录机器人使用的账号并加入测试群。爸爸、家属、机器人须使用不同的群内显示名；不要有同名成员或同名群。自动化运行时保持在该群，避免手动切换聊天或翻页。
3. 先只检查一次：

```powershell
.\.venv-wechat\Scripts\python.exe wechat_bridge.py --once
```

检查会打开指定群、核对群类型和名称、读取当前可见消息用于建立起点，并向本机服务发送状态；**不会下载图片、上传消息正文或发出微信消息**。不用 `--once` 时会持续检查。初始可见历史全部跳过。

4. 关闭先前的检查进程，使用下面的命令启动实际模式，再到网页开启“允许正式微信收发”：

```powershell
.\.venv-wechat\Scripts\python.exe wechat_bridge.py --send
```

命令行 `--send` 和网页开关必须同时满足，才处理正文和发送消息。单独开启任意一项都不发送。服务重启会关闭真实开关；不要设置无人值守重启和自动重发。

5. 由配置的爸爸或家属在测试群发送一条新的纯文本读数，再发送机器人返回的 `确认 编号`。核对网页记录、群回复和发送状态；配置好图片模型后，再分别测试仪表照片、食物照片和家属代发照片，核对识别与确认步骤；也要测试关闭开关和断开桥接。只有这些实际通过，才说明对应版本和该账号完成了基本连通测试。

默认桥接地址为 `http://127.0.0.1:8765`，令牌从 `data/config.json` 的 `bridge_token` 读取。自定义服务数据目录时指定相应文件：

```powershell
.\.venv-wechat\Scripts\python.exe wechat_bridge.py --token-file "D:\your-folder\config.json" --send
```

也可通过 `HEALTH_BOT_BRIDGE_TOKEN` 环境变量提供令牌。不要把令牌写进命令行参数或提交到代码仓库。桥接只接受本机数字回环 HTTP 地址，拒绝远程地址和重定向。

### 收发边界和停止方式

- 仅受理一个指定普通群内、两个指定显示名发送的新文字或图片消息，忽略自身及其他人的消息；不处理语音、文件和其他群。名称是界面信息，**不是可靠的账号身份认证**；成员改名或重名时应立即停用并重新核对。
- 启动时只建立当前历史起点；已经出现的消息不补处理。界面消息 ID 仅在本次会话中用于去重。作者说明 UI ID 会随界面变化、消息 hash 也可能重复，因此无法保证永久唯一或恰好一次处理。
- 程序只在初始化时选择群。收发前后核对当前群；发现群改变、可见消息 ID 整体重建或配置改变就停止。部分界面变化仍可能无法可靠识别，因此所有读数都必须通过编号再次确认才保存。
- 发送按队列逐条领取，每条只尝试一次。发送或回执结果不明确时停止，不自动重试。此时先查看实际群聊，避免人工重新发起造成重复；网页状态也可能落后于实际发送结果。
- 默认每 5 秒轮询，不保证及时送达。窗口卡住或服务不可用时，家属仍需要按原有照护安排主动联系爸爸。
- 用 `Ctrl+C` 停止桥接；网页也可关闭真实开关。更换群、重新登录或恢复失败后，应由操作者核对窗口并重新启动；重启会建立新的会话起点，期间消息不会补发。

## 数据与验证范围

`data/` 保存本地 SQLite 健康数据、设置、API 密钥和桥接令牌。文件没有额外加密，使用 Windows 账户权限保护；备份时包含整个目录，并保存在受控位置。不要把该目录、导出 CSV 或截图提交到公共仓库。网页登录入口仅在本机提供；不要自行通过端口转发暴露服务。

当前已做桥接模拟验证：默认模式不转发正文、不下载图片、不取发送队列；历史跳过；发送者及自身过滤；相同读数的新消息可受理；返回的回复不被重复直接发送；固定群检查；发送回执失败不重发；错误目标拦截；整批 UI ID 重建时停止；拒绝非本机服务地址。图片测试覆盖临时文件清理、路径外逃拒绝、大小限制、处理失败后继续接收、API 结果不明时不重传，以及下载期间切群或关停后的拦截。**这些测试使用模拟微信对象，不等于实机群收发验收**。未验证你的授权、实际微信兼容性、锁屏恢复和长期在线稳定性。

可在项目目录复现全部本地测试；测试不会导入 `wxautox4` 或操作真实微信：

```powershell
python -m unittest discover -s tests -v
```

其中 `tests/test_wechat_bridge.py` 包含 25 个桥接模拟测试。仅运行这些测试可加上 `-p test_wechat_bridge.py`。
